# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Cal.diy — community/MIT fork of Cal.com with all enterprise (EE) code stripped. **Do not introduce EE-style features** (Teams, Organizations, Insights, Workflows, SSO/SAML, license-key gating). The repo is intended to remain 100% MIT, no Open Core split, no hosted version.

## Monorepo layout

Turborepo + Yarn 4 workspaces. Most commands are run from the repo root and routed through Turbo with `--filter`.

- `apps/web` — Next.js 16 app (`@calcom/web`). Hybrid App Router (`app/`) + Pages Router (`pages/`). The `pages/api/**` routes still host the v1 REST API.
- `apps/api/v2` — `@calcom/api-v2`, a NestJS Platform API (separate build/test toolchain — Jest, not Vitest).
- `apps/docs` — docs site.
- `packages/prisma` — Prisma 6 schema, ~600 migrations, seed scripts, Kysely codegen.
- `packages/trpc` — tRPC server + React client, split tsconfigs for `server` vs `react` builds.
- `packages/features` — domain logic grouped by feature (bookings, availability, eventtypes, etc.). New code generally lives here, not in `apps/web`.
- `packages/lib` — shared utilities, server repositories (`packages/lib/server/repository`, aliased as `@calcom/repository/*`).
- `packages/app-store` — third-party integrations. Has its own `CONTRIBUTING.md`. **Do not hand-edit `apps.*.generated.*` / `bookerApps.metadata.generated.ts` / `analytics.services.generated.ts`** — they are regenerated by `yarn app-store:build` (run automatically by the pre-commit hook).
- `packages/embeds/*` — embed-core, embed-react, embed-snippet (published to npm).
- `packages/platform/*` — atoms SDK (`@calcom/atoms`), platform-constants/enums/types/utils/libraries — these are *built* artifacts consumed by `apps/api/v2`, so changes there usually require rebuilding the platform packages.
- `packages/ui` and `packages/coss-ui` — shared UI; `coss-ui` is mirrored from external source via `scripts/pull-coss-ui-components.ts`.

## Linting & formatting

Biome 2 is the only linter/formatter (no ESLint, no Prettier). Config: `biome.json`. Pre-commit (`lint-staged.config.mjs`) runs `biome lint --reporter summary --config-path=biome-staged.json` on changed JS/TS files and `prisma format` on the schema. The pre-commit hook **also runs `yarn app-store:build` and stages the regenerated files** — expect generated `packages/app-store/*.generated.*` to appear in your commits. Don't `--no-verify` to skip this; rerun the hook after fixing the underlying issue.

## File naming conventions

For new repository/service classes (from `CONTRIBUTING.md`):

- Repositories: `Prisma<Entity>Repository.ts` exporting `class Prisma<Entity>Repository`.
- Services: `<Entity>Service.ts` exporting `class <Entity>Service`. Avoid generic names like `AppService`.
- **Do not** use `.service.ts` / `.repository.ts` dot-suffixes on new files (existing ones are being migrated). Reserve dot-suffixes for `.test.ts`, `.spec.ts`, `.types.ts`, `.timezone.test.ts`, `.integration-test.ts`.

## Path aliases (apps/web)

Defined in `apps/web/tsconfig.json`:

- `~/*` → `apps/web/modules/*`
- `@components/*`, `@pages/*`, `@lib/*`, `@server/*` → corresponding `apps/web/*` dirs
- `@calcom/repository/*` → `packages/lib/server/repository/*`
- `@coss/ui/*` → `packages/coss-ui/src/*`

Vitest mirrors these aliases in `vitest.workspace.ts`.

## Test structure

`vitest.workspace.ts` defines ~16 named projects (e.g. `@calcom/lib`, `@calcom/features`, `@calcom/ui`, `@calcom/web/components`, `@calcom/web/modules/views`, `@calcom/embeds`). Mode is selected by env var, not CLI flag (Vitest 4 dropped custom flags):

- default mode runs all unit/spec tests except `*.timezone.test.ts`, `*.integration-test.ts`, `packages/embeds/**/packaged/**`
- `VITEST_MODE=timezone` (also requires `TZ=...`) runs `*.timezone.test.ts`
- `VITEST_MODE=integration` runs `*.integration-test.ts`
- `VITEST_MODE=packaged-embed` runs the packaged embed tests

Playwright projects live under `playwright.config.ts`: `@calcom/web`, `@calcom/app-store`, `@calcom/embed-core` (+ firefox/webkit/isMobile variants), `@calcom/embed-react`. The `webServer` config starts `next start` on port 3000 with `NEXT_PUBLIC_IS_E2E=1`; ensure no other dev server is occupying that port.

## Database

Prisma 6 + Postgres. Single schema at `packages/prisma/schema.prisma` (referenced from the root `package.json`'s `prisma` block). Migrations are sql under `packages/prisma/migrations/`. After editing the schema, generate migrations with `yarn workspace @calcom/prisma db-migrate`. Kysely types are generated alongside (`prisma-kysely`).

Seed entrypoint: `packages/prisma/seed.ts`. Default seeded credentials are listed in `README.md` (admin: `admin@example.com` / `ADMINadmin2022!`).

## Yarn resolutions / patches

The root `package.json` has a large `resolutions` block pinning transitive deps (security CVEs and version-conflict fixes) and several patches under `.yarn/patches/` (notably `dayjs`, `next-i18next`, `libphonenumber-js`). When upgrading deps, check both the resolution map and patches — bumping a patched package without refreshing the patch will break the build.

## Working rules for this repo

### Rule 1: The web layer never touches the database outside tRPC
- `PrismaClient` is imported EXCLUSIVELY in `packages/trpc/server/routers/*`
- Never import or use `PrismaClient` inside `apps/web/`
- Need a new database query? Add a tRPC procedure and call it from the component
- Why: layered architecture where the database is not directly reachable from UI components

### Rule 2: Every tRPC mutation uses protectedProcedure + inline ownership check
- Mutations MUST use `protectedProcedure`, never `publicProcedure`
- State-changing mutations (update/delete/mark) fetch the resource and verify `ctx.user.id` owns it BEFORE the DB write
- On ownership mismatch: `throw new TRPCError({ code: "UNAUTHORIZED" })`
- Pattern reference: existing ownership checks in handlers (e.g. update.handler.ts - fetch record, compare userId, throw or proceed)
- Why: publicProcedure on a mutation lets anyone with the endpoint URL modify data. Inline ownership checks keep the guard visible at the callsite - no hidden helper magic.

## PR conventions

From `CONTRIBUTING.md`: target ≤500 LOC and ≤10 code files per PR, single concern. Split DB/schema changes from app logic; do prep refactors in their own PR. Add a changeset (`yarn changesets-add`) for any change that should appear in the published `@calcom/atoms` release notes.
